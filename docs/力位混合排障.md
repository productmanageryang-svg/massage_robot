# 力位混合诊断

如果按摩/艾灸时**推得动但不回弹**，或者感觉不到力控，按这里的步骤做，
把输出发回来就能定位。

代码层面已经验证过：仓库里的力位混合和「第三版」逐条命令一致
（`scripts/compare_v3_force_path.py`）。所以问题一定在环境，不在代码。

---

## 一条命令拿到诊断

在部署的那台机器上（`/opt/heacon`，或你自己的 clone 目录）：

```bash
cd /opt/heacon
sudo -u heacon .venv/bin/python scripts/diagnose_force.py > /tmp/heacon-diag.txt 2>&1
cat /tmp/heacon-diag.txt
```

把 `/tmp/heacon-diag.txt` 整个发回来。

脚本是**只读**的：不下发运动指令，力控最多开 2 秒然后关掉，结束把机械臂
恢复到待机。不会让机械臂动。

---

## 它看什么

| 段落 | 看什么 | 异常意味着 |
|---|---|---|
| 1. 环境 | `HEACON_SIMULATE` 是否为 False | 为 True 说明连的是假机械臂 |
| | `pyrealsense2` 是否可用 | 缺失则摄像头不工作，服务起不来 |
| 2. 标定文件 | 文件名是 `handeye.json` 还是 `handeye.example.json` | 示例文件 = 没在本机标定过 |
| 3. 工作高度 | 艾灸 `-40`、按摩 `-30` | 和卷尺实测法兰到皮肤的距离对比 |
| 4. **力控存活** | `ft` 什么时候从 2 变 0 | **最关键的一项** |
| 5. 结论 | 对照 A / B 两种情况 | |

---

## 第 4 段怎么读

力控打开后控制器进入「搜索」状态（`ft=2`），找不到接触面就会自己退出
（`ft=0`）。在空气里这是正常行为，现场机器上大约 1.2 秒。

```
t= 0.00s  fsm=25  ft=2  力控在线
t= 1.25s  fsm=33  ft=0  力控已关闭     <- 空中退出，正常
```

关键不是这个数字本身，而是**服务过程中的日志**。请一并检查：

```bash
grep "moxa spring" /var/log/heacon/console.log | tail -20
```

- **看不到任何 `moxa spring` 行** → 情况 A：力控根本没活着。
- **看得到，但 `F=(0.0,0.0,0.0)`** → 情况 B：平衡点和当前位置重合。
- **看得到，且 `F=` 有明显数值** → 力控在正常工作，问题在别处。

---

## 情况 A：力控没活着

原因：华炎力控是搜索模式。第三版靠「降到工作高度时正好贴到皮肤」赶在
自动退出之前建立接触。换一台机器后，只要工作高度偏离皮肤几毫米，就会
错过这个窗口，静默退化成位置控制——手推得动，但不回弹。

**先确认标定。** 这是最常见的原因：

1. `config/handeye.json` 等三个文件必须是本机实测值，不能是 `*.example.json`
2. 用卷尺量：机械臂在「工作高度」时，法兰到皮肤的实际距离应该是
   - 艾灸：30 mm
   - 按摩：40 mm

差得多，就重新标定。

## 情况 B：有日志但 F 一直是 0

平衡点（`_hybrid_home`）和当前位置重合，误差为 0，目标力自然为 0。
通常是穴位坐标被算到了工具当前位置，而不是皮肤上——还是标定的问题。

---

## 需要发回来的内容

1. `scripts/diagnose_force.py` 的完整输出
2. `grep "moxa spring" /var/log/heacon/console.log | tail -30`
3. 服务的完整日志：`tail -100 /var/log/heacon/console.log`
4. 用卷尺量的「法兰到皮肤」实际距离
5. 三个标定文件的文件名（`ls /etc/heacon/`）
