# 从零部署

从一台空电脑到能控制机械臂，一步一步。按顺序做，每步都有验证命令。

有两个场景，先判断自己在哪个：

| 场景 | 要做的事 |
|---|---|
| **A. 新电脑接机械臂和相机** | 第 1～7 节，全部 |
| **B. 只是想看看代码能不能装** | 第 1～2 节即可，第 3 节起需要硬件 |

---

## 1. 准备

### 1.1 系统

推荐 **Ubuntu 24.04 LTS**（现场 NUC 就是它）。其他 Linux 发行版原理相同，包名可能不同。
macOS 也能跑，但不建议用于现场：相机需要 root 和额外驱动。

```bash
lsb_release -a          # 应显示 24.04
python3 --version       # 需要 3.11 或更高；24.04 自带 3.12
uname -m                # x86_64
```

### 1.2 系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git \
                    libgl1 libglib2.0-0 libegl1 libgles2 \
                    v4l-utils usbutils openssl
```

`libgl1` / `libglib2.0-0` 是 `opencv-python-headless` 链接的库。缺了会在
`import cv2` 时报 `libGL.so.1: cannot open shared object file`。

### 1.3 网络必须能到机械臂

这是最容易忽略、也最容易失败的一步。

```bash
ip -4 addr show | grep inet          # 确认本机有 192.168.0.x 地址
ping -c 2 192.168.0.10               # 机械臂控制器
timeout 3 bash -c 'cat < /dev/null > /dev/tcp/192.168.0.10/10003' && echo OPEN
```

**不通就不要往下做。** 后面每一步都会失败，而且报错不会指向这里。

怎么连上取决于现场：

- **WiFi**：机械臂自带热点（NUC 上叫 `E05L-Pro-PE078201004`），连上后通常自动分配
  `192.168.0.x`。NUC 当时是 `192.168.0.100`。
- **网线**：与机械臂同交换机，手动配同网段地址。

确认自己能拿到 `192.168.0.x`，不要和机械臂 `.10` 撞车。

## 2. 装程序

```bash
git clone https://github.com/productmanageryang-svg/massage_robot.git
cd massage_robot

python3 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
```

依赖约 46 个包，其中 mediapipe 拉进来的传递依赖最多。**必须能联网**，
首次安装约 5～10 分钟。

### 2.1 如果 pip 装不上

| 报错 | 原因 | 处理 |
|---|---|---|
| `No matching distribution found for scipy==1.16.3` | Python 版本太低 | 需要 3.11+，见 1.1 |
| `libGL.so.1: cannot open` | 缺系统库 | 回到 1.2 |
| `mediapipe` 编译失败 | 平台无 wheel | 确认 x86_64 + Linux/macOS |

### 2.2 验证安装

```bash
python main.py --print-config
python -c "import heacon.motion.route, heacon.vision.hybrid_geom; print('imports ok')"
```

`--print-config` 会打印解析后的路径和端口。**看 `robot` 那一行是不是
`192.168.0.10:10003`**，不是就设环境变量 `HEACON_ROBOT_HOST`。

## 3. 相机：从 NUC 换到这台电脑

**这一步是换机的关键。** RealSense 是 USB 设备，同一时刻只能被一台电脑独占。

### 3.1 先拔线，再做别的

从 NUC 上拔下 RealSense 之前，先在那台机器上停掉占用相机的服务：

```bash
# 在 NUC 上（如果你能登录）
sudo systemctl stop heacon-camera
```

不停也不会损坏硬件，只是新机器可能看不到设备。两台机器同时插着是**不可能的**——
一根线只能插一台。

### 3.2 插到新电脑

- 优先 **USB 3.0 口**（蓝色/SS 标识，或 USB-C 标 TB3/USB3.2）
- **不要**走无供电的 hub、不要用长延长线
- RealSense 对线材很敏感，原装线最好

### 3.3 Linux 权限（只需做一次）

```bash
sudo cp deploy/udev/99-realsense-d435i.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger

# 把当前用户加进 video 组，然后重新登录（不是重启）
sudo usermod -aG video $USER
groups | grep video      # 应能看到 video
```

**重要**：`usermod` 之后必须**重新登录**才生效。只开新终端不算。

### 3.4 确认相机在

```bash
lsusb | grep -i intel           # 应看到 8086:0b3a  RealSense 435i
v4l2-ctl --list-devices         # 应列出 /dev/video0..5
```

`lsusb` 看不到 = 系统层面没认到，不是代码问题。依次排查：换口、换线、换机器试。

### 3.5 用脚本确认能取流

```bash
python scripts/check_hardware.py
```

它会真的打开一次相机，读一帧彩色 + 一帧深度。**深度帧必须有**——
穴位识别靠深度，没有深度就只能显示画面、无法开始服务。

正常输出应该像：

```
[PASS] 设备       RealSense D435I serial=261222075744 ...
[PASS] 取流       color=(1280, 720, 15) depth=(848, 480, 15)
[PASS] 彩色帧     1280x720
[PASS] 深度帧     848x480（识别必需）
```

如果 `usb_type` 显示 USB2，把线换到 USB3 口——USB2 带宽不够跑 1280x720。

## 4. 标定

**换电脑 ≠ 需要重新标定**，因为标定是相对机械臂和相机的，不是相对电脑的。

但有两种情况必须重新标定：

1. **相机换了安装位置或角度**（拆装过、换了支架）
2. **机械臂换了底座位置或换了床**

只换电脑、其他都没动，直接把标定文件放好即可：

```bash
ls config/
# handeye.json  color_calib.json  work_home.json
```

仓库里只有 `*.example.json`（是现场机器上的一份真实标定）。**如果你的相机和
机械臂安装位置与现场不同，这三个文件必须重新标定**，否则穴位会算到错误位置。

## 5. 启动

### 5.1 前台跑（先这样验证）

```bash
source .venv/bin/activate
python main.py all
```

三个进程一起起：控制台 8765、平板入口 8766、相机采集。

打开浏览器 `http://127.0.0.1:8765/`：

- 能看到实时画面 → 相机通了
- 设备状态显示"已连接" → 机械臂通了
- 两个都通，才点"开始扫描"

### 5.2 后台跑（正式用）

```bash
sudo deploy/install-ubuntu.sh
```

它会建用户、装服务、配 udev、生成证书、装模型，并把三个 systemd 服务设为开机自启。

服务名和压缩包里的不同（改成了统一入口）：

| 压缩包 | 本仓库 |
|---|---|
| `heacon-bridge` | `heacon-console` |
| `heacon-camera` | `heacon-camera` |
| `heacon-gateway` | `heacon-tablet` |

```bash
systemctl status heacon-console heacon-tablet heacon-camera
journalctl -u heacon-console -f
```

## 6. 平板

平板浏览器打开 `https://<这台电脑的IP>:8766`。

自签证书会提示不安全，选"继续访问"。平板必须走 HTTPS，因为浏览器只在
安全来源下允许麦克风。

## 7. 开机的顺序问题

`heacon-wait-net.service` 会等到本机拿到 `192.168.0.x` 地址，再启动另外三个服务。
没有它，冷启动时服务会先起来、网络后到，结果就是"设备已离线"，要手动重启才好。

`install-ubuntu.sh` 会自动装上，不需要手动配置。

## 8. 排查

| 现象 | 先查什么 |
|---|---|
| 页面能开，画面是黑的 | `python scripts/check_hardware.py`，看相机那一段 |
| 画面正常，显示"设备已离线" | 机械臂网络：`ping 192.168.0.10` |
| 识别不出人体 | 深度帧是否正常；深度图是识别的唯一依据 |
| 推得动但不回弹 | `python scripts/check_force_control.py`，看力控是否活着 |
| 开机后要手动重启才连上 | `heacon-wait-net` 服务是否 enabled |
| 服务起不来 | `journalctl -u heacon-console -n 50` |

## 9. 关于 Windows

**当前不支持。** 不是配置问题，是这些依赖：

- systemd 服务 → Windows 没有，需要换成 Windows 服务或任务计划
- `/tmp` 与文件权限模型 → 已改成可配置路径，但 RealSense 的 USB 权限机制不同
- 三个进程的守护 → 需要额外工具（如 NSSM）

技术上可行，但没有实测过。需要做一轮专门的移植和验证，不能只靠读代码断言。

如果一定要在 Windows 上用，最稳的做法是：**装 WSL2 + Ubuntu 24.04，
按本文档部署**，USB 直通用 `usbipd-win` 把相机透传进 WSL。这条路径同样需要实测。
